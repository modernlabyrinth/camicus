# Planned after the 0.1.0 alpha

These are proposed next steps, not implemented capabilities or promised dates.
Prioritize them using observed installation and workflow friction, while preserving
explicit authorization, private evidence and truthful unknown results.

1. **Guide real weekly inputs.** Help an owner select project context and task
   records, review them and create the two declared snapshots without handcrafting
   JSON. Any connector is opt-in with separately authorized access; no connectors
   exist in this alpha. Acceptance: an owner can prepare valid inputs, review each
   included fact, see omitted/unknown fields and complete a check without silently
   inventing records or changing real timestamps to pass.
2. **Broaden Mac evidence and useful explanations.** Collect integration fixtures
   on actually tested supported macOS/Python combinations, including denied,
   missing, truncated and unexpected output. Acceptance: record exact environments
   and tool outcomes; every unavailable observation stays explicit; explain the
   next bounded action and relevant limitations without claiming a machine is
   simply “safe” or treating every listener as a vulnerability.
3. **Run 3–5 external installation/use pilots.** Recruit willing owners, observe
   setup, first run, interpretation and removal, then turn reproducible friction
   into versioned fixes. No external pilots are claimed yet. Acceptance: retain
   consented, sanitized feedback; document successes and failures; agree a feasible
   maintainer review/patch cadence and publish its actual version history. Keep
   vulnerabilities private and avoid promising an unsupported response SLA.
